# iM 이룸 — 개발 현황

최종 갱신: 2026-09-20

이 문서는 PRD·TRD와 실제 코드 사이의 차이를 기록한다. 기능을 추가하거나 제약이 달라지면 같은 변경에서 함께 갱신한다.

## 현재 단계

서비스 소개와 주요 고객·상담사 화면, 합성 데이터 기반 계산·재설계 시나리오가 동작하는 공모전 프로토타입 단계이다. 실제 금융 연동과 운영 시스템 단계는 아니다.

| 영역 | 상태 | 비고 |
|---|---|---|
| 소개·고객·상담사 UI | 구현 | 고객 홈 기본 진입, 모바일 하단 내비게이션 적용 |
| 합성 재무 데이터 | 구현 | 고정 fixture 중심 |
| 고객 페르소나 | 구현 | 사회초년생·주거 준비·소득 위험 3종, 전체 상태 동시 전환 |
| 최종기획서 적용 예시 모드 | 구현 | 28세·월 260만원·보증금 3,000만원의 24개월 여정 대시보드 |
| Frontend/Backend 경계 | 구현 | `frontend/src`, `backend` 디렉터리와 실행 진입점 분리 |
| 재무 계산·목표 배분 | 구현 | 자격 미확인 상품 자동 배분 차단 |
| 사용자 목표 설계 | 구현 | 재무진단 직후 7단계 입력(종류·금액·기한·준비 금액·우선순위·모으는 방식·미리보기). 건너뛰면 추천 목표 사용 |

| 새는 돈 탐지 | 미구현 | 미사용 구독·리볼빙 이자 후보와 근거 거래 모델 필요 |
| 변화 감지 | 부분 구현 | 소득·지출 중심, 복합 이벤트·결측 판단 보강 필요 |
| 정책 판정 | 부분 구현 | 연령·거주지·일부 소득 규칙만 지원 |
| 정책 변경 | 데모 구현 | S05에서 버전·납입 한도 변경 재현 |
| 계획 승인·거절 | 구현 | 목표 수정도 신규 제안 계획으로 처리 |

| 월간 수집 | 데모 구현 | 가상 시계와 월말 기준일 계산, 작업 큐·재시도 미구현 |
| Claude 결과 설명 | 구현 | `POST /api/ai/explain`. Schema 검증 후 준비된 설명 → 규칙 기반 설명으로 대체 |
| Claude 제한형 상담 | 구현 | `POST /api/ai/counsel`. 조회 전용 도구 6종, 출처·기준일 표시, 위험 시 상담사 연결 |

| AI 비식별 처리 | 구현 | 화이트리스트 재구성 + 자유 입력 패턴 삭제. `npm run ai:validate`로 검증 |
| Claude live 호출 검증 | 검증 | Vercel 운영 환경에서 `claude-sonnet-5` 정책 구조화 요청 HTTP 200, `source=CLAUDE`, `isFallback=false`, `needsHumanReview=true` 확인 |
| 담당자 정책 검수 화면 | 미구현 | 구조화 초안을 검수해 `policyRules.ts`에 반영하는 UI는 없다. 현재는 파일 수정으로만 반영 |
| Gemini 설명 | 구현(레거시) | 기존 `/api/explain-plan`, `/api/qa`. 현재 화면은 사용하지 않으며 정리 대상 |

| 목표 연쇄·중도해지 방어 | 미구현 | 다음 목표 전환과 손실·대안 비교 시나리오 필요 |
| 영속 저장 | 미구현 | 새로고침 시 상태 초기화 |
| 자동 테스트 | 미구현 | 핵심 경계 사례 우선 도입 필요 |
| 실제 금융 연결 | 범위 제외 | 실제 마이데이터·계정계·송금 없음 |

## 최근 결정

- 목표 수정은 기존 승인 계획을 덮어쓰지 않고 새 `PROPOSED` 계획을 만든다.
- 사용자가 설계한 목표는 Mock 계약에 선택 필드로 더한다(`POST /plan/preview`, `POST /plans`의 `goals`, `GET /personas/:id/goals`). 값을 주지 않으면 기존 응답과 같다.
- 요청 본문의 목표는 신뢰하지 않는다. 범위·형태·연결 상품을 검증한 뒤에만 계산에 넘기고 어긋나면 400으로 거절한다.
- 계획 ID는 목표 내용이 아니라 고객·버전·기준 스냅샷에서 나온다. 목표를 바꿔도 승인·거절·모의 실행 멱등성은 그대로이다.
- 세션은 등록한 목표를 기억해 월간 점검의 조정안도 같은 목표로 계산한다.
- 고객 화면에서 `남기는 금액`·`생활 유동성`·`생활비로 남겨두는 돈`은 `잔액`으로 통일한다.
- 로고는 초록색 곡선형 M 도형(`BrandMark`)을 쓰고 흰색 상단 바에 회색 굵은 `iM이룸` 워드마크를 나란히 둔다.
- `NEEDS_VERIFICATION` 또는 `INELIGIBLE` 상품에는 자동으로 자금을 배분하지 않는다.
- 모의 실행 키는 고객·계획 버전·기준 스냅샷 조합으로 고정한다.
- 정책 변경 시나리오는 알림에서 끝내지 않고 정책 데이터와 제안 계획을 갱신한다.
- 프로덕션 서버는 ESM 형식으로 빌드한다.
- 일반 고객 화면에서는 내부 버전·시나리오·상담사 전환을 숨기고 `?demo=true`에서만 시연 도구를 노출한다.
- 일반 접속은 고객 재무 홈으로 시작하며 모바일은 4개 핵심 메뉴를 하단 고정 바로 제공한다.
- 자격·월 납입·예상 기간 문구는 현재 계산 결과와 상태를 그대로 반영한다.
- 소개 화면의 시나리오 주입 카드와 동작도 `?demo=true`에만 노출한다.
- 페르소나 선택 시 고객, 동의일, 스냅샷, 목표, 정책 판정, 계획을 하나의 세션으로 초기화한다.
- 제출 대응 역할을 백엔드, 프론트엔드, 병합 및 배포, QA 및 디버깅으로 분리하고 모든 기능 작업은 최신 `dev`에서 분기한다.
- 생성형 AI 공급자는 Claude API로 정하고 역할을 언어 처리로 제한한다. 계산·판정은 규칙 엔진, 정책 반영은 담당자 검수, 계획 변경은 사용자 승인, 위험 대응은 상담사가 맡는다.
- AI 응답은 `CLAUDE / FIXTURE / RULE` 출처를 항상 함께 반환하고 화면에 표시한다.
- AI 호출은 재시도하지 않는다. 실패는 재시도 대신 준비된 응답과 규칙 기반 설명으로 처리한다.
- 상담 답변의 상담사 연결 판정은 규칙 엔진 결과를 우선한다. 모델이 다르게 답해도 덮어쓴다.

## 다음 우선순위

1. 월간 수집 작업, 계획·승인·실행 이력을 서버 저장소에 영속화한다.
2. 모바일 실제 기기 사용성 검증과 홈 카드의 정보 밀도 조정을 진행한다. 목표 설계 단계의 입력 검증·되돌리기 사례도 함께 확인한다.
3. S07 거절, S08 철회, S09 중복 실행·LLM 장애 시나리오를 추가한다.
4. 계산·자격·월말·철회·중복 실행 자동 테스트를 작성한다.
5. 검수된 정책 문서 검색(RAG)과 담당자 검수 화면을 연결하고, 사용하지 않는 Gemini 경로를 정리한다.
6. 최근 거래 범위·완전성을 표시하고 구독·리볼빙 비용 후보 탐지를 추가한다.
7. 만기·중도해지·다음 목표 전환 시나리오를 추가한다.

## 완료로 간주하지 않는 항목

- 화면에 데이터가 보이는 것만으로 월간 스케줄러가 구현된 것은 아니다.
- 목표를 직접 입력할 수 있다는 이유로 목표 입력이 영속 저장되는 것은 아니다. 새로고침하면 세션과 함께 사라진다.
- 승인 버튼을 누를 수 있다는 이유로 서버 수준 멱등성이 보장되는 것은 아니다.
- 합성 시나리오 결과를 실제 고객의 금융 성과로 해석하지 않는다.
- Gemini가 답변한다는 이유로 정책 자격이나 금융 계산의 정확성이 검증된 것은 아니다.
- Claude가 설명을 만든다는 이유로 금액·자격이 검증된 것은 아니다. 숫자의 근거는 규칙 엔진이다.
- 정책 구조화 초안이 만들어졌다는 이유로 정책 규칙 DB에 반영된 것은 아니다. 담당자 검수가 남아 있다.
- 운영 환경에서 Claude 정책 구조화 호출은 검증했지만, 설명·상담의 응답 품질과 장시간 장애 복구까지 검증된 것은 아니다.
